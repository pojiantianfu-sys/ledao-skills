# 02_爆款对标与改稿执行规则 V1.0

# 一、用途

本规则用于处理：
- 用户提供对标爆款，希望迁移到自己的赛道
- 用户已经写好原稿，希望诊断或修改
- 用户提供"对标＋自己的原稿"
- 用户希望借鉴某篇内容的标题、开头、结构或传播逻辑

核心原则：
先判断用户给了什么，再决定改什么。
不要拿到任何素材都重新创作。

# 二、先识别任务类型

## 1. 用户只要求诊断

例如：
"这篇怎么样？"
"能不能发？"
"哪里有问题？"

此时先诊断。

不得默认全文重写。

如果原稿已经成立，应明确告诉用户可以直接发，最多给最小修改建议。

## 2. 用户要求修改自己的原稿

默认原则：
能局部修改，不整体推翻。

优先保留：
- 原稿真正想表达的核心判断
- 作者本人真实观点
- 已经不错的标题和开头
- 真实案例
- 有辨识度的表达
- 已经成立的结构

优先修改：
- 重复
- 逻辑断点
- 客户不精准
- 开头过慢
- 抽象表达
- AI套话
- 高客单承接不足
- 平台风险

## 3. 用户提供爆款对标

不要马上改写。

先判断：
"这篇内容为什么能够传播？"

拆解至少包括：
- 标题点击机制
- 开头代入方式
- 核心冲突
- 信息推进顺序
- 情绪张力
- 反转逻辑
- 具体场景
- 收藏、评论或转发动机

这些属于传播资产。

# 三、爆款迁移的核心原则

爆款迁移不是：
原文 → 换几个行业名词。

也不是：
看完原文 → 自己重新写一篇同主题文章。

正确方式是：
保护已经验证的传播机制，再换成当前用户自己的内容。

可以借：
- 标题母题
- 冲突机制
- 开头方式
- 结构推进
- 阅读节奏
- 信息密度
- 情绪变化方式

不能直接移植：
- 对标作者独有案例
- 对方个人经历
- 对方客户经历
- 对方独有观点
- 高辨识度原创表达
- 未经核实的数据
- 未经验证的专业结论

# 四、不要把爆款改普通

改稿时必须特别检查：
- 原稿最吸引人的冲突有没有被削弱
- 最有力量的判断有没有被改成普通知识
- 具体场景有没有被改成抽象理论
- 反转有没有消失
- 原稿为什么让人继续往下读，修改后这个动力还在不在

例如：
原稿：
"你每天都在解决孩子的问题，但家里真正没有被处理的，是大人之间的关系。"

不建议机械改成：
"家庭教育需要关注整体家庭系统。"

后者可能更专业，却削弱了原来的传播力。

专业化不能以牺牲用户理解和阅读动力为代价。

# 五、标题优先保护点击机制

如果用户提供的标题已经来自验证过的内容，优先研究：
"它为什么让人想点？"

不要因为另一个标题：
"更专业"
"更完整"
"更高级"

就自动替换。

尤其避免把：
冲突型标题
改成：
知识型标题。

正确做法通常是：
保留已经验证的标题母题＋替换为当前用户的精准人群、场景或问题。

同时避免与原标题完全相同。

# 六、开头优先让用户认出自己

陌生流量内容的开头优先进入：
- 用户正在经历的状态
- 具体问题
- 具体场景
- 冲突
- 一个明确判断

不要默认：
"最近我遇到一个客户……"

除非作者本人就是流量入口，或者这个真实故事本身具有很强的阅读动力。

通常优先考虑：
用户 → 问题 → 判断 → 案例/作者。

# 七、具体优先于抽象

用户更容易代入：
"每次跟孩子聊学习，最后都会变成吵架。"

而不是：
"亲子沟通模式存在结构性问题。"

因此改稿时优先寻找：
- 人物
- 时间
- 动作
- 对话
- 现实选择
- 冲突
- 可以观察的行为

专业判断可以随后出现。

不要用抽象概念代替用户正在经历的生活。

# 八、案例必须承担证明作用

案例不是为了让文章显得专业。

使用案例前问：
"这个案例究竟证明前面的哪个判断？"

如果一个案例只是在说：
"我有一个客户也是这样。"

但不能推进观点，应考虑删除。

案例最好包含：
处境 → 具体问题 → 关键片段 → 作者判断 → 实际变化/发现。

不得为了符合对标结构自行编造案例。

没有真实案例时，可以改用：
- 用户提供的真实经历
- 已明确属于典型场景的描述
- 普遍现象

但必须明确性质，不得伪装成真实客户。

# 九、不要为了完整不断加内容

常见错误结构：
结论；
解释；
案例；
再次解释；
总结；
再升华。

如果案例已经把判断讲清楚，就进入下一部分。

每一段至少应该增加一种新东西：
- 新事实
- 新场景
- 新冲突
- 新判断
- 新问题
- 新的处理方向

如果只是换一种方式重复上一段，删除。

# 十、不要追求"每段都是金句"

自然表达允许：
解释、停顿、过程、具体描述、适量重复强调。

但不要机械连续使用：
"不是A，而是B。"
"真正的问题从来不是……"
"你以为……实际上……"
"底层逻辑……"
"最高级的……"

如果每一段都在反转，容易产生明显AI感。

# 十一、改稿不能改变事实

允许：
- 调整顺序
- 压缩重复
- 强化冲突
- 优化标题
- 改善口语
- 提炼作者已经表达出的判断

不得：
- 创造作者没有表达过的专业观点并冒充本人观点
- 编造经历
- 编造客户
- 编造数据
- 编造效果
- 编造资历

如果某个事实会明显增强文章，但用户没有提供：
指出需要补充什么。

不要替用户补。

# 十二、改稿优先级

默认按照以下顺序处理：
第一：真实性与平台安全。
第二：目标客户是否正确。
第三：标题和开头是否有传播力。
第四：原稿核心观点是否成立。
第五：结构和信息推进。
第六：高客单承接。
第七：语言润色。

不要在定位和结构都存在问题时，只做漂亮的文字润色。

# 十三、什么时候应该大改

只有以下情况才优先考虑整体重构：
- 选题与目标客户明显错位
- 标题与正文完全不一致
- 核心观点无法成立
- 内容大部分属于泛知识
- 原稿结构严重阻碍理解
- 存在大量平台风险
- 用户明确要求重新创作

否则：
优先少改。

# 十四、对标＋原稿任务的推荐流程

同时拿到对标和用户原稿时，按顺序判断：

第一步：对标为什么有效？
找传播资产。

第二步：用户原稿已经继承了什么？
不要重复修改已经做对的部分。

第三步：哪些只是表面模仿？
例如只换人群名词，却没有换案例和专业判断。

第四步：哪些是真正属于用户自己的东西？
重点保护。

第五步：进行最必要的修改。

最终目标不是：
"写出另一篇漂亮文章。"

而是：
保留对标的传播优势，同时让最终内容真正属于当前作者。

# 十五、公开版边界

本规则只提供：
传播结构分析、对标拆解、内容诊断和改稿方法。

不得借对标任务：
- 复制他人独特表达
- 冒用他人案例
- 伪造原创
- 引入任何未公开的内部商业方法或私有案例
